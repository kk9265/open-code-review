# 按单号归集与 AI 审查队列

左侧“审查”默认进入[审查结果](http://127.0.0.1:5484/reviews)，查看已完成、失败等历史轮次，支持搜索和分页。切换“审查队列”页签进入 <http://127.0.0.1:5484/reviews/queue>，这里只显示排队及运行中的任务和提交归属操作。草稿独立位于 `/reviews/drafts`。

审查结果采用左右布局：左侧以仓库、分支、需求单为父级目录，下面按时间从新到旧积累历史轮次，右侧阅读所选报告。目录显示当前归属提交数，各轮显示其冻结提交数；复审次数不会累加成提交总数。分组按 50 个分页，组内保留所有历史轮次，搜索支持标题、单号及仓库。左侧底部固定“未分类”，显示未归属提交的总数，点击后可搜索、分页和关联需求单。列表与详情优先展示提交日志中的中文标题，单号 URL 作为小字显示。正文支持 Markdown 标题、列表、加粗、代码块和表格；已保存的原始结果保持不变，渲染时禁用原始 HTML 和危险链接。提交范围、模型输入与重试操作折叠在详情下方。

## 当前配置

- 跟踪 `zgame/master`、`zgame_china/dev/1.1.15.235.1`，每 300 秒同步。
- 模型连接：AI Mana；模型：`glm-5.3`（用户最新指定）；队列已启用，不限制每轮累计 Token 用量。
- Windows 自动读取 `%LOCALAPPDATA%/.aimana/proxy.json` 的当前代理端口。AI Mana 必须保持运行，无需复制其密钥。
- Linux 可使用手动 API 地址，当前执行器支持兼容 OpenAI Chat Completions 的服务。非本地服务从 `OCR_LLM_API_KEY` 读取凭据。

## 从提交到结果

1. 提交并推送到已跟踪的分支。只有跟踪起点之后发现的提交参与归集。
2. 提交日志中包含一个完整飞书链接，例如 `https://project.feishu.cn/zg/story/detail/7131560109`。也支持 `issue/detail/单号`。
3. 按仓库、分支、完整单号链接归组；不同项目空间或 story/issue 类型不会串单。没有链接、多个链接、合并提交进入“待归类”。
4. 同单号已有待执行任务时，后续提交加入该任务；开始时固定提交 SHA 列表和模型配置。
5. 全局只有一个运行中的任务。运行期间的新提交创建下一轮；每轮包含当前归属于该单的全部已发现提交，并附上上一轮完成结果作为参考。
6. 页面展示轮次、状态、完整提交差异输入及 AI 结果。当前列表最多显示最近 100 轮和 100 条提交，待归类优先。

## 人工操作

- 在结果详情的“备注与反馈”中补充业务背景或指出误报。“保存备注”仅保存，不调用 AI。
- 右上角“重新审查”与“提交反馈并重新审查”使用输入框当前内容，附上所选原轮次结果，以原提交列表创建独立复审轮次，使用当前模型配置。无须先保存；也可不填写反馈直接复审。
- 新轮次保存已提交反馈快照，并提供返回上一轮的链接。后续编辑备注不会改写已提交的反馈。重复提交旧页面会被拒绝，刷新后再操作。

- 展开“提交归属”，填写目标飞书链接，点击“调整归属并入队”。可以移到已有单号；旧的已固定轮次不会被改写，后续轮次采用新归属。
- 合并提交手动归类后，使用相对第一父提交的差异，需确认其中变更归属。
- “暂停队列”停止开始新任务，当前任务继续；“取消排队”仅取消尚未开始的轮次。
- 失败或中断可以“按原输入重试”，新建独立重试记录；模型、预算和提交列表沿用原记录。AI Mana 的传输端口重新发现。
- 修改模型或预算后，用右上角“重新审查”创建新轮次；原结果保留。
- 重启后待执行任务继续，原运行中任务标记为中断，避免不知情地重复调用模型。
- 仓库归档后，不开始它的新轮次。

## 审查范围与限制

网页按单号审查采用自主工具循环，复用 `internal/llm` 模型客户端与 `internal/tool` 文件读取、查找和搜索；CLI 自己的执行器保持不变。所选提交仍逐个相对第一父提交生成差异，不把中间其他单号的修改纳入目标。工具默认读取最后一个所选提交，也允许所选提交及其父版本的完整 SHA；分支名和范围外版本被拒绝。

新轮次不再创建疑点清单，不要求 `question_id` 或状态更新。模型直接查询代码、阅读上下文，认为证据足够后直接返回 Markdown 报告。工具响应保留在会话历史中，包括原生协议要求的推理回放信息。到达执行限制或请求失败时才单独请求阶段性报告；报告生成失败仍保留查阅证据。旧轮次的疑点记录仍可查看，不迁移或删除历史数据。

可选的 CodeGraph/Wiki 在独立本地服务中运行。设置页的“外部上下文”地址留空即停用。主程序仅调用版本化只读查询接口，不引入第三方索引依赖、安装器或 Wiki 写入逻辑。索引准备由服务完成并锁定到本轮最终 SHA；Wiki 按仓库和分支读取已批准文章并冻结内容。服务不可用时保留基础审查，同时将缺失能力记录到本轮证据中。接口、维护命令和数据目录见 [独立上下文服务](../integrations/context-service/README.md)。

搜索支持 `search_terms`（最多 8 个字面关键词任选其一）与明确的 `search_mode=literal/regex`。未指定模式的 `A|B` 会被拒绝并提示纠正，避免把错误查询当作无匹配证据。相同工具、版本和参数的重复查阅返回已有证据编号。

查阅阶段最多 24 次模型请求、80 次代码查阅；模型直接交付报告后可提前结束。总时限仍为 15 分钟，其中最后 3 分钟预留给报告生成。单次读取最多 500 行，搜索/文件查找最多 100 个结果，工具正文最多 24000 字节，截断须缩小范围补查。设置页的累计 Token 限制默认关闭；开启时仍限制整轮的累计请求，包括单独报告请求，不会为收尾绕过用户预算。每轮冻结模型、提交列表及预算配置，复审采用当前设置，按原输入重试沿用原设置。

单个差异上限 1 MiB，累计差异上限 2 MiB；超限会失败而非静默截断初始差异。单次模型输出使用默认模板的 16384 tokens 上限；响应被截断时不会执行其中的工具调用，已保存的查阅记录保留。每轮最长 15 分钟，失败不阻塞下一任务。仅提供只读工具，不修改工作区、分支或源库，不执行仓库脚本，也不推送或回写 Gitea。

队列、输入结果和代码查阅记录保存在同一 SQLite 数据库，迁移版本为 8。维护脚本使用 `--pause-workbench` 前，应先暂停 AI 队列并等当前任务完成。数据库升级前备份保存在 `.local-go/before-context-*`，不要用旧二进制直接打开升级后的数据库。
